# MADDAW 設計ドラフト v1.1(シンセ方式)

> 状態: たたき台。「11. 論点」の決定に応じて更新する。
> v1.1 での変更: 調査レポート([research.md](research.md))の売り ★1〜★4 を設計の中心に据えた。
> v1.0 での変更: 「ノートごとに事前変換して並べる」方式(v0.x)をやめ、素材を音源にしたシンセ(サンプラー)をノートでリアルタイムに鳴らす方式にした。v0.x と Phase 0 のコードは git の履歴(`b5aa39c`)に残っている。

## 1. コンセプト

**素材を入れたら、もう楽器。** VocalShifter とサンプラーを1つにした、ブラウザで動く音MAD用DAW。

いまの主流は、REAPER・VocalShifter・WaveTone・Melodyne を組み合わせる作り方である。ソフトの間で WAV を書き出しては読み込む往復が必要になる(research.md 1.1)。MADDAW では、素材の解析、ピッチの整形、シンセ化、演奏、打ち込みまでを、1つの画面で、往復なしで行う。

### 売り(このアプリが勝つ理由)

| | 売り | 解決する痛点 |
|---|---|---|
| **★1** | **往復なしで完結する。** 切り出し→音程判定→ピッチ整形→シンセ化→打ち込みを1つの画面で行う。編集はすべて非破壊(元の素材とパラメータを保持し、音声ファイルを作り直さない)。無料で、Windows・Mac・iPad で動く | 4つのソフトを行き来する手間。VocalShifter と WaveTone が Windows 専用であること |
| **★2** | **素材の音程を、セント単位で自動判定する。** 「D4 −37¢」まで出すので、平均律に乗っていない喋り声でも合う。判定結果はピッチカーブとして見え、誤りは手で直せる | 素材の音程が分からない。半音単位では合わない |
| **★3** | **抑揚の残し具合を、1本のスライダーで決める。** 0%(元の抑揚のまま)〜100%(完全に平坦)。VocalShifter の「平均化・平坦化」を、連続した量として扱う | 人力(抑揚を残す)とシンセ化(平坦にする)で、手順もソフトも別になっている |
| **★4** | **サンプラーの欠点を潰した「素材シンセ」。** 子音を保護するシンセ化マーカー、長さ保持で高音でも切れない、ステレオ対応、ピッチベンド、ADSR | 高音で途中で切れる、伸ばすと間抜けになる、原型が残らない、モノラルになる、ピッチベンドしにくい |

補助的な売り: 劣化の目安表示(★5)、音MAD向けの初期設定(★6)、iPad で歌わせる音MADが作れる(★7)。

### 引き継ぐ前提
- ピアノロールでノートを入力する。対象は PC と iPad。音質はなるべく自然に。
- TapMV と同じ構成(Vite + TypeScript、UI フレームワークなし)。TapMV のフォルダには触らない(流用するコードはコピーする)。

### やらないこと(初期スコープ外)
- オーディオ録音、VST などのプラグイン、オートメーション全般、TapMV との連携、映像の扱い

## 2. 基本フロー(★1: 1画面で完結)

```
① 素材を読み込む ─────────────▶ 自動解析(ピッチカーブ・基準ピッチ・有声区間・立ち上がり)
② 素材エディタで整える
     ・鳴らす範囲を決める
     ・基準ピッチを確認する(★2。外れていたら直す)
     ・抑揚の残し具合を決める(★3)
     ・シンセ化マーカーを置く(★4。自動で提案される)
   └ 編集中は、画面の鍵盤ですぐに試し弾きできる
③ トラックに楽器を割り当て、ピアノロールで打ち込む
④ 再生・調整 → WAV で書き出す
```

完了の目安: **素材を読み込んでから30秒以内に、鍵盤で弾ける状態になる**(自動解析と自動提案だけで、とりあえず鳴る)。

## 3. 素材の解析(★2)

素材を読み込んだときに Worker で1回だけ行い、結果を保存する(再計算もできる)。

| 解析 | 方法 | 使い道 |
|---|---|---|
| ピッチカーブ(f0) | pYIN(Phase 0 で実装・テスト済み) | 表示、基準ピッチの判定、PSOLA、抑揚の調整 |
| 有声らしさ・音量 | pYIN と RMS | 有声と無声の区別、シンセ化マーカーの提案 |
| 基準ピッチ | 有声フレームを音量で重み付けした中央値。セント単位(Phase 0 で検証済み。合成音での誤差は数セント) | ノートとの差を決める |
| ピッチマーク | 声帯の振動1回ごとの位置(Phase 0 で実装済み) | PSOLA で再生する |
| 立ち上がり | エネルギーの変化から検出する(TapMV の `onsets.ts` をコピーして使う) | 発音位置の提案 |

### 解析結果の手直し(VocalShifter の「ピッチ誤検出の修正」に相当)
ノイズの多い素材は解析を誤る(VocalShifter と同じ弱点)。そこで、次の手直しをできるようにする。
- 区間を選んで「オクターブ上/下に直す」「無声にする/有声にする」
- 基準ピッチの線をドラッグする、または音名とセントを直接入力する
- 手直しした結果は、ピッチマークと基準ピッチの計算にそのまま反映する

## 4. 素材シンセ(★3・★4)

### 4.1 シンセ化マーカー(★4)

素材を最大4つの区間に分け、それぞれの鳴らし方を変える。

```
素材:  [ s  |  a ~~~~~~~~~~~~~~~~~~~ | ぁ… ]
        頭部 ▲    持続区間              ▲ 語尾
        (子音)発音位置                リリース開始
```

| 区間 | 鳴らし方 |
|---|---|
| **頭部**(発音位置より前) | 1回だけ、伸縮せずに鳴らす。**子音を保護する**ため。ノートの頭より前に出して鳴らす(前ノリ)ので、リズムが自然になる |
| **持続区間** | ノートが続く限り伸ばす。伸ばし方は「PSOLA で周期を繰り返す」(既定。声の母音にとても自然)/「ループ」(クロスフェード付き)/「伸ばさない」から選ぶ |
| **語尾**(任意) | ノートを離したあとに鳴らす。語尾の息や下がり方を残せる |

- 区間の境目は、解析結果から**自動で提案する**。頭部は最初の安定した有声区間の手前まで、持続区間は f0 と音量が最も安定している区間。
- 提案された境目は、波形の上でドラッグして直せる。
- 「伸ばすと間抜けになる」「子音が潰れる」という痛点(research.md P5)への直接の答えになる。VocalShifter の TIME の制御点を、楽器の設定として持つイメージ。

### 4.2 ピッチの決まり方(★3)

ボイスが鳴っている各時点の目標ピッチは、次の式で決める。

```
目標(t) = ノート + ベンド(t) + グライド(t) + ビブラート(t)
          + (1 − 平坦化) × (f0(t) − 基準ピッチ)
```

- **平坦化**(抑揚の残し具合)は 0〜100%。
  - 0% = 素材の抑揚がそのまま、ノートの高さに平行移動する。REAPER のピッチ変更と同じ。
  - 100% = 抑揚を完全に消して、ノートの高さに固定する。VocalShifter の平坦化と同じで、シンセ化に向く。
  - 楽器ごとに既定値を持ち、ノートごとに上書きもできる。
- **ビブラート**: 平坦化で消えた揺れの代わりに、LFO で付け直せる(深さ・速さ・かかり始めの遅れ)。VocalShifter の「ビブラート付加」に相当する。
- **ベンドとグライド**: ピアノロールにピッチベンドを書ける。グライドはノート間の滑らかなつなぎ。「サンプラーではピッチベンドが難しい」という痛点(P6)への答え。
- 平坦化が 0% のときは、素材の f0 から計算するのをやめて、一定量のシフトとして処理する。そのほうが軽く、誤差も出ない。

### 4.3 ピッチの変え方
- **長さ保持**(既定): TD-PSOLA で処理する。フォルマントが自然に保たれ、高音でも素材が短くならない(★4)。フォルマントのずらし量(半音)も指定できる。目安は ±1 程度(調査より)。
- **速度連動**: 昔ながらのサンプラーの音(高いほど短く、声も高くなる)。
- **Signalsmith**(後のフェーズ): 和音や雑音の多い素材向け。遅延と処理負荷が大きいため、リアルタイムではなく、編集時に音の高さごとの音声をあらかじめ作ってキャッシュする方式にする。

### 4.4 シンセ部分
| 部分 | 内容 | フェーズ |
|---|---|---|
| アンプ | ADSR、ベロシティによる音量変化 | 1 |
| 発音 | ポリ(同時発音数)/モノ/レガート(つながったノートでは鳴らし直さず、ピッチだけ移す) | 1(ポリ)、3(モノ/レガート) |
| ステレオ | ステレオ素材は、左右を同じピッチマークで処理してステレオのまま鳴らす(★4) | 1 |
| ピッチ | ベンド、グライド、ビブラート用の LFO | 2 |
| フィルター | ローパス/ハイパス、レゾナンス、エンベロープでの変化量 | 3 |

### 4.5 劣化の目安(★5)
- ピアノロールのノートを、基準ピッチからの移調量で色分けする(±3 半音を超えたら注意、±7 を超えたら警告)。
- 音域が合わない場合は「オクターブ違いの素材を楽器に追加する」ことを勧める(多重サンプル。後のフェーズ)。

## 5. 音声エンジン

```
[UI スレッド] 編集 ──(曲データ・パラメータ)──▶ [AudioWorklet: Engine]
       ▲                                       ・シーケンサー(サンプル単位)
       │ 解析結果                                 ・ボイス: 素材シンセ(PSOLA / 速度連動)
[Worker: 解析]                                  ・ミキサー・メーター
```

- **シーケンサーも Worklet の中に置く。** WAV の書き出しは、同じ Engine を OfflineAudioContext で実行するだけで済み、再生と書き出しの結果が一致する。
  - Safari の OfflineAudioContext で Worklet が動くかは、実機で確認する。動かなければ、Engine のコードを直接まとめて処理する予備の経路を用意する。
- **PSOLA をリアルタイムで鳴らす**: ピッチマークは事前に解析してあるので、再生時はグレイン(声帯の振動1回分の波形)を、目標ピッチの間隔で重ねていくだけ。遅延は数ms。Phase 0 では出力1秒あたり約3msの負荷で、多くの音を同時に鳴らせる。
- **素材データの渡し方**: SharedArrayBuffer が使えれば共有メモリに置き、使えなければ転送する(必須にはしない)。
- **iPad**:
  - メモリは素材とキャッシュ合わせて 200〜300MB 以内に収める(Safari はタブごとの上限が厳しい)。
  - 同時発音数は端末の性能に合わせて自動で決める。
  - マナーモードでも音が鳴るように、`audioSession` を設定する。
  - Web MIDI は Safari が非対応なので、画面の鍵盤で弾く。

## 6. データモデル

時間の単位は **tick(PPQ = 960)**。

```ts
Project { version, id, name, tempo: TempoEvent[], timeSig: TimeSigEvent[], sources: Source[], instruments: Instrument[], tracks: Track[] }

Source {                            // 読み込んだ元ファイル(音声本体は blobStore)
  id, name, blobId, sampleRate, channels, durationSec
  analysis?: SourceAnalysis         // 解析のキャッシュ(消えても再計算できる)
}

SourceAnalysis { hopSec, f0: Float32Array, voicedProb, rms, pitchMarks: Int32Array, onsets: number[] }

Instrument {
  id, name, sourceId
  range: { start, end }                        // 秒。鳴らす範囲
  corrections: PitchCorrection[]               // 解析結果の手直し(3章)
  root: { midi: number, mode: "auto" | "manual" }  // 例 61.63 = D4 −37¢(★2)
  markers: {                                   // シンセ化マーカー(★4)
    attack: number                             // 発音位置 = 頭部の終わり
    sustain: { start, end, mode: "psola" | "loop" | "none" }
    release?: number                           // 語尾の開始
  }
  pitch: {
    mode: "preserve-length" | "resample"
    flatten: number                            // 0–1(★3)
    formantSemitones: number
    vibrato: { depthCents, rateHz, delaySec }
    glideSec, bendRange
  }
  amp: { attack, decay, sustain, release, velocitySens }
  voice: { mode: "poly" | "mono" | "legato", maxVoices }
  filter?: { type, cutoffHz, resonance, envAmount }   // Phase 3
}

PitchCorrection { start, end, kind: "octave-up" | "octave-down" | "unvoiced" | "voiced" }

Track { id, name, color, instrumentId, gainDb, pan, mute, solo, notes: Note[], bends: BendPoint[] }

Note { id, tick, duration, pitch, velocity, flatten?: number }   // flatten はノートごとの上書き

BendPoint { tick, cents }
```

│          │  ・素材エディタ(★1〜★4 の中心。下で詳述)          │
│          │  ・ミキサー                                   │
├──────────┴───────────────────────────────────────┤

### 素材エディタ(このアプリの顔)

```
┌───────────────────────────────────────────────┐
│ 基準ピッチ: D4 −37¢ [自動]   平坦化 ━━━●━━━ 40%      │
├───────────────────────────────────────────────┤
│ D4 ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄  ← 基準ピッチの線   │
│      ╱‾‾‾∿∿∿∿∿∿∿‾‾‾‾╲    ← 元のピッチ(橙)           │
│      ━━━━━━━━━━━━━━━    ← 平坦化したあと(黄)        │
│ ▁▃▅▇█████████████▇▅▃▁   ← 波形                    │
│  │頭部│     持続区間     │語尾│  ← シンセ化マーカー     │
├───────────────────────────────────────────────┤
│ ADSR / 伸ばし方 / フォルマント / ビブラート      [▶ C4] │
└───────────────────────────────────────────────┘
```
- 元のピッチ(橙)と、整えたあとのピッチ(黄)を重ねて表示する。VocalShifter と同じ色の約束にして、乗り換える人が迷わないようにする。
- 平坦化のスライダーを動かすと、黄色い線がその場で変わる。鍵盤で弾けば、変化をすぐ耳で確かめられる。

## 8. 入出力・保存
- 素材: wav / mp3 / ogg / flac / m4a、動画の音声(WAV のみの VocalShifter と違い、そのまま読み込める)
- ノート: ピアノロール。MIDI ファイルの読み込みは Phase 2(耳コピ済みの MIDI を使うため)
- 書き出し: WAV(ミックス)。トラックごとの書き出しと、楽器を「シンセ化した WAV」として書き出す機能は Phase 2(REAPER と併用する人のため)
- 保存: IndexedDB に自動保存し、元に戻すにも対応する。プロジェクトファイルにも保存できる。上書き事故を防ぐため、保存先を明示する(VocalShifter の弱点への対策)

## 9. 技術スタック
- Vite + TypeScript、UI フレームワークなし、Vitest / Playwright
- DSP は TypeScript で書く(pYIN と PSOLA は Phase 0 のコードを Worklet 向けに作り直す)。重ければ WASM に移す
- 依存ライブラリは MIT / BSD 系だけにする(Signalsmith は MIT。Rubber Band は GPL なので使わない)
- 公開: Cloudflare(静的配信。`_headers` で COOP/COEP を設定)

## 11. 論点(要決定)

- **B. ピッチの変え方の既定**: 長さ保持(PSOLA)を既定にし、速度連動も選べる、でよいか。調査結果も長さ保持を支持している
- **C. フェーズの振り分け**: 上の Phase 1〜4 でよいか
- **D. 素材を使わないオシレーター**: のこぎり波などの普通のシンセ音を入れるか。調査では、vital で音作りする制作者もいた
- **E. Phase 0 のコード**: 検証ページは削除し、pYIN と PSOLA は Worklet 向けに作り直して残す、でよいか
- **F. 語尾(リリース区間)**: ノートを離したあとに語尾を鳴らす機能は、Phase 1 に入れるか(自然さには効くが、実装が増える)
- **G. 平坦化の既定値**: 0%(REAPER と同じ)か、ある程度平坦にした値(例 50%)か。歌に聞こえやすくなる効果とのバランスを、実際の素材で決めたい

(論点 A「基準キーの決め方」は、★2 に合わせて「セント単位で自動判定し、手で直せる」に決定した。)
