# MADDAW 設計ドラフト v0.2

> 状態: たたき台。「11. 論点」の決定に応じて更新していく。
> v0.2 の変更: TapMV 連携を外した。ノート入力をピアノロールに、音質の目標を「なるべく自然」に、対象環境を PC と iPad に決めた。技術スタックを TapMV に合わせた。音程合わせの仕様(4章)を詳しくした。

## 1. コンセプト

**取り込んだ素材の平均的な音の高さを自動で判定し、ピアノロールに書いたノートの高さに合わせて、素材全体の音程を上下させて楽曲にするブラウザDAW。**

- 声の抑揚は残す。素材のピッチカーブをまるごと平行移動して合わせる(REAPER でアイテムのピッチを半音・セント単位で上下させるのと同じ考え方)。完全な平坦化(オートチューン)はしない。
- 音質はなるべく自然にする。フォルマント(声質)を保ったままピッチシフトする。
- 対象は PC(Chrome / Edge / Safari)と iPad(Safari)。

### やらないこと(初期スコープ外)
- TapMV との連携、オーディオ録音、VST/プラグイン、オートメーション全般、テキスト記法でのノート入力、Web MIDI(iPad の Safari が非対応のため)

## 2. 基本フロー

```
① 素材を読み込む(音声 / 動画ファイル)
② 素材を自動で解析する: ピッチカーブ、平均の音の高さ(=基準ピッチ)、発音位置
③ 必要なら切り出し範囲・基準ピッチ・発音位置を手で直す
④ トラックに素材を割り当て、ピアノロールでノートを書く
⑤ 再生して確認 → ノートごとに微調整(セント、抑揚の幅など)
⑥ WAV で書き出す / プロジェクトを保存する
```

## 3. データモデル

時間の単位は **tick(PPQ = 960)**。秒への変換はテンポマップで行う。

```ts
Project {
  version, id, name
  tempo: TempoEvent[]            // { tick, bpm }  MVP では1つだけ
  timeSig: TimeSigEvent[]        // { tick, num, den }
  sources: Source[]
  samples: Sample[]
  tracks: Track[]
}

Source {                         // 読み込んだ元ファイル
  id, name, blobId               // 音声本体は blobStore に置く
  sampleRate, channels, durationSec
}

Sample {                         // 素材から切り出した「鳴らす単位」
  id, name, sourceId
  start, end                     // 秒(元ファイル内の区間)
  analysis: SampleAnalysis       // 自動解析の結果(4.1)。キャッシュなので消えても再計算できる
  rootPitch                      // 基準ピッチ。MIDI番号(小数)。例 62.37 = D4 +37セント
  rootPitchSource: "auto" | "manual"
  attack                         // 発音位置(秒, start からの相対)。ノートの頭をここに合わせる
  gainDb, fadeIn, fadeOut
}

SampleAnalysis {
  hopSec                         // 解析の間隔(例 5ms)
  f0: Float32Array               // フレームごとの基本周波数(MIDI番号, 無声音は NaN)
  voicing: Float32Array          // 有声らしさ 0–1
  rms: Float32Array
  centerPitch                    // 自動判定した平均の音の高さ(4.2)
  confidence                     // 判定の信頼度 0–1
}

Track {
  id, name, color
  sampleId                       // 1トラック1素材(論点 A)
  defaults: NoteParams           // トラック全体の既定値
  gainDb, pan, mute, solo
  notes: Note[]
}

Note {
  id, tick, duration             // tick
  pitch                          // MIDI番号(整数)
  velocity                       // 0–1
  params?: Partial<NoteParams>   // ノートごとの上書き
}

NoteParams {
  cents: number                  // 微調整(±100)
  contour: number                // 抑揚の幅 0–1.5(1 = 元のまま, 0 = 平坦)(4.3)
  formant: number                // フォルマントのずらし量(半音、0 = 声質を保つ)
  lengthMode: "oneshot" | "stretch" | "loop"
  sampleOffset: number           // 素材のどこから鳴らすか(秒)
}
```

## 4. 音程合わせの仕様(コア機能)

### 4.1 解析(素材を取り込んだとき、Worker で実行)
1. モノラルに変換する。解析用に 16kHz 前後へダウンサンプルして処理を軽くする。
2. **pYIN** でフレームごとの f0 と有声らしさを求める。間隔は 5ms、探索範囲は 50〜1000Hz。
3. RMS を求め、無音区間を判定する。
4. 発音位置を推定する。TapMV の `onsets.ts`(立ち上がり検出)を流用し、「最初の有声区間の始まり」と比べて決める(4.4)。

### 4.2 平均の音の高さ(基準ピッチ)の判定
- 対象は「有声らしさ ≥ 0.5 かつ無音でない」フレーム。
- 周波数そのものではなく、**半音単位(対数)の値**で平均をとる。周波数のまま平均すると、高い音に引っ張られる。
- 外れ値(オクターブの誤検出、語尾のしゃくりなど)に強いよう、**音量で重み付けした中央値**を基本にする。
  - 候補: 重み付き中央値(既定)/重み付き平均/最頻値(ヒストグラムの山)。精度の比較は Phase 0 で行う(論点 H)。
- 信頼度が低いとき(有声フレームが少ない、ばらつきが大きい)は警告を出し、手で設定するよう促す。
- 打楽器・ノイズのように音程のない素材は「音程なし」として扱う。ノートの高さは、基準音 C4 からの差として再生速度で反映する。

### 4.3 ピッチを合わせる式

フレームごとに、目標のピッチを次の式で決める:

```
shift      = (note.pitch + cents/100) - rootPitch     // 半音
target(t)  = rootPitch + shift + contour × (f0(t) - rootPitch)
```

- `contour = 1`(既定): 素材のピッチカーブをそのまま平行移動する。抑揚はそのまま残る。**これが基本動作。**
- `contour < 1`: 抑揚を基準ピッチに向かって縮める。0 にすると完全に平坦になる(オートチューン)。
- `contour > 1`: 抑揚を大げさにする。
- `contour = 1` のときは、ずらし量が素材全体で一定になる。そのため、単純な一定量のピッチシフトで処理でき、最も音質が良い。

### 4.4 タイミング
- 素材の **発音位置(attack)** を、ノートの頭に合わせる。例えば「さ」の子音のように有声音より前にある部分は、ノートの頭より前にはみ出して鳴る。こうすると、リズムが自然に聞こえる。
- 発音位置の決め方は、自動(最初の有声区間の始まり、または立ち上がり)/手動/素材の頭、から選べる。

### 4.5 長さの合わせ方 `lengthMode`

| モード | ノートが素材より短い | ノートが素材より長い |
|---|---|---|
| `oneshot`(既定) | ノートの終わりで短くフェードアウト | 素材が終われば無音 |
| `stretch` | 縮める | 伸ばす(最大2倍程度まで、超えたら警告) |
| `loop` | 切る | 指定したループ区間を繰り返す |

自然さを優先するため、既定は `oneshot` にする。`stretch` は、ピッチシフトと同じ処理の中で一緒に行う。

### 4.6 品質の目安
- 移調量が ±7 半音を超えると、どの方式でも不自然になりやすい。ピアノロールのノートを移調量に応じて色分けし、極端な移調に気付けるようにする。
- 移調量の大きいノートには、オクターブ違いの素材を使い分けるか、`formant` の微調整を勧める。

## 5. 音声処理エンジン

### 5.1 ピッチシフトの方式(Phase 0 で比較して決める)

| 方式 | 長所 | 短所 | ライセンス |
|---|---|---|---|
| **signalsmith-stretch** | 声以外の素材にも強い。フォルマント補正あり。WASM版あり | 時間とともに変わるピッチ(`contour ≠ 1`)は、細かく区切って処理する必要がある | MIT |
| **TD-PSOLA**(自作) | 単声の声なら非常に自然。フォルマントが自然に保たれる。時間変化するピッチにも素直に対応できる | f0 推定の精度に依存する。和音や雑音の多い素材は苦手 | 自作 |
| **WORLD**(分析・再合成) | f0 カーブを自由に書き換えられる。フォルマントも独立に操作できる | 音がややこもる。息の多い声や雑音で劣化しやすい | 修正BSD |

**仮の方針**: `contour = 1` の基本動作は signalsmith-stretch(フォルマント補正あり)で処理する。`contour ≠ 1` は TD-PSOLA で処理する。どちらも「素材 → 目標ピッチカーブ → 出力」という同じインターフェースで隠し、あとから方式を差し替えられるようにする。

### 5.2 処理の流れ

```
[UI スレッド] 編集・描画
     │ ノートの変更
     ▼
[Render Worker ×1〜2]  ノートごとに処理した音声を生成
     │ キャッシュキー = hash(sampleId, rootPitch, shift, contour, formant, 長さ, lengthMode)
     ▼
[AudioWorklet: Mixer]  スケジュール再生、音量・パン、メーター
```

- **処理済みの音声を事前に作って再生する(プリレンダ)。** 重い処理をリアルタイムで回さずに済み、再生と書き出しの結果が完全に一致する。
- 同じ高さ・同じ長さのノートはキャッシュを共有する。音MADは同じ音の繰り返しが多いので効果が大きい。
- 処理が間に合っていないノートは、仮の音(再生速度を変えるだけの簡易処理)で鳴らし、処理が終わったら差し替える。
- WAV の書き出しは、同じキャッシュをオフラインでミックスするだけで済む。

### 5.3 iPad への対応
- **メモリ**: Safari はタブあたりの使用量が厳しい。キャッシュはモノラル Float32 で持ち、合計 256MB などの上限を設けて LRU で捨てる。元の素材は長くても、使う区間だけデコードして保持する。
- **マナーモード**: TapMV の `audioSession.ts` と同じく `navigator.audioSession.type = "playback"` を設定し、マナーモードでも音が鳴るようにする。
- **WASM**: SIMD は Safari 16.4 以降で使える。対応していない環境では、SIMD なしの版に切り替える。
- **SharedArrayBuffer**: COOP と COEP の両方が必要。TapMV の `_headers` には COOP しかないので、COEP(`require-corp`)を追加する。外部リソースを使わない構成なので、問題は出ない見込み。
- **AudioContext**: ユーザーが画面に触れてから開始する(Safari の制約)。

## 6. 画面構成

```
┌──────────────────────────────────────────────────┐
│ ヘッダー: プロジェクト / 元に戻す / 再生 / BPM / 拍子 / 書き出し │
├──────────┬───────────────────────────────────────┤
│ 素材一覧   │ トラック一覧(各トラックのノートを小さく表示)     │
│ (波形の    ├───────────────────────────────────────┤
│  サムネイル │ 下部パネル(切り替え):                        │
│  と基準音)  │  ・ピアノロール(選択中のトラック)              │
│          │  ・素材エディタ(波形 + ピッチカーブ + 基準音の線) │
└──────────┴───────────────────────────────────────┘
```

### ピアノロール
- ノートを、元の素材からの移調量で色分けする(4.6)。
- **ノートの中に、合わせた後のピッチカーブを薄く重ねて表示する。** 抑揚がどの音の高さに乗るかが見える。これが REAPER にない、このアプリの特徴になる。
- ノートを選ぶと、インスペクタで `cents` / `contour` / `formant` / `lengthMode` を変えられる。
- 操作: PC はマウスとキーボード(描く・選ぶ・移動・長さ変更・複製)。iPad は「描く/選ぶ」の切り替えボタン、2本指でスクロールとズーム、長押しでメニュー。
- 描画は Canvas で行う。ノートが数千個あっても重くならないように、表示範囲だけを描く。

### 素材エディタ
- 波形に f0 カーブを重ねる。基準ピッチは横線で表示し、ドラッグで動かせる。発音位置は縦線で表示する。
- 切り出し範囲を指定する。試聴は、元の音と、指定した高さに合わせた音を切り替えて聴ける。

## 7. 入出力

| 種類 | 形式 | 備考 |
|---|---|---|
| 素材の入力 | wav / mp3 / ogg / flac / m4a、動画の音声 | 動画は mediabunny で音声だけ取り出す(TapMV と同じ) |
| ノートの入力 | ピアノロール、MIDI ファイルの読み込み(Phase 2) | TapMV の `midi.ts` を流用できる |
| 音声の出力 | WAV(ミックス)、トラックごとのステム(Phase 2) | 44.1 / 48kHz、16 / 24bit |
| プロジェクト | ファイル保存(素材込み) | TapMV の `.madproj` と同じ仕組み |

## 8. 保存
- TapMV の仕組みを流用する: IndexedDB に自動保存(`persistence` / `blobStore`)、元に戻す(`history`)、プロジェクトファイル(`projectFile`)。
- 解析結果とプリレンダのキャッシュは保存しない(再計算できるため)。ただし解析に時間がかかる場合は、解析結果だけ保存する。

## 9. 技術スタック(TapMV に合わせる)
- Vite + TypeScript。UI フレームワークは使わない(TapMV と同じく、自前の `Store<T>` と DOM の組み立て)
- テスト: Vitest(DSP・解析・データ処理)、Playwright(画面操作)
- DSP: signalsmith-stretch(WASM)。TD-PSOLA と pYIN は TypeScript で書き、遅ければ WASM に移す
- 公開先: Cloudflare Workers の静的アセット(`_headers` に CSP / COOP / COEP を設定)
- **TapMV と共通化できるもの**: `Store`、`history`、`idb` / `blobStore` / `persistence`、`projectFile`、`onsets`、`midi`、`audioSession`、`touch`、`i18n`。MVP ではコピーして使い、共通パッケージにするかは後で決める(論点 I)。

### Phase 0 の途中経過(2026-10-19、PC の Chrome、合成音声で計測)
- pYIN による基準ピッチ: 合成音声(しゃくり・ビブラート・語尾下がり付き)で、真の値との差は中央値 −8¢、最頻値 −6¢。平均は −15¢で、しゃくりと語尾に引っ張られる。中央値を既定にする案を支持する結果。
- 処理速度(出力1秒あたり): 再生速度 ≈1ms、TD-PSOLA ≈3ms、Signalsmith ≈22〜52ms。いずれも目標の 100ms を大きく下回る。
- Signalsmith の注意点: 予約した変更は、より後の時刻の変更を予約すると消えてしまう。そのため、ピッチを時間とともに動かす(contour ≠ 1)場合は、OfflineAudioContext を一時停止しながら変更を渡す必要がある。変更が音に反映されるまでには、レイテンシの約半分(約65ms)かかるので、その分早めに渡す。
- 未実施: 実際の声素材での聴き比べ、iPad での計測。

## 11. 論点(要決定)

- **A. トラックと素材の関係**: 1トラック1素材でよいか。それとも、ノートごとに別の素材を選べるようにするか。→ 案: MVP は1対1。データ構造には余地を残す
- **H. 「平均キー」の定義**: 重み付き中央値(既定案)でよいか。それとも「一番長く伸ばしている音」を優先するか。Phase 0 の結果を見て決める
- **I. TapMV とのコード共有**: コピーで始めるか。それとも最初から共通パッケージ(モノレポ)にするか
- **J. 和音**: 同じトラックで複数のノートを同時に鳴らすことを許すか(処理上は可能。人力ボーカルでも、ハモりに使える)
- **K. 公開とライセンス**: TapMV と同じく無料公開か。依存ライブラリはすべて MIT / BSD 系にする前提で進める
