## 1. コンセプト

**素材を入れたら、もう楽器。** VocalShifter とサンプラーを1つにした、ブラウザで動く「人力のための」音MAD用DAW。

いまの主流は、REAPER・VocalShifter・WaveTone・Melodyne を組み合わせる作り方で、ソフトの間で WAV を書き出しては読み込む往復が必要になる。MADDAW では、素材の解析、ピッチの整形、シンセ化、演奏、打ち込みまでを、1つの画面で往復なしに行う。

### 売り

| | 売り | 解決する痛点 |
|---|---|---|
| **★1** | **往復なしで完結する。** 切り出しから打ち込みまでを1画面で行う。編集は非破壊(元の素材への参照とパラメータだけを持ち、音声ファイルを作り直さない)。無料で、Windows・Mac・iPad で動く | 4つのソフトの往復。VocalShifter と WaveTone が Windows 専用であること |
| **★2** | **素材の音程をセント単位で自動判定する。** 判定結果はピッチカーブとして見え、誤りは手で直せる | 素材の音程が分からない。喋り声は半音単位では合わない |
| **★3** | **抑揚の残し具合を、スライダー1本で決める**(0〜100%)。楽器全体にも、ノートごとにも、素材の一部の区間にもかけられる | 人力(抑揚を残す)とシンセ化(平坦にする)で手順が分かれている。頭の「こぶし」だけ消したい |
| **★4** | **サンプラーの欠点を潰した「素材シンセ」。** 子音を守るシンセ化マーカー、長さ保持で高音でも切れない、ステレオ、ピッチベンド、ADSR、自然な持続音 | 高音で途中で切れる、伸ばすと間抜けになる、原型が残らない、モノラルになる、ピッチベンドしにくい |

補助的な売り: 劣化の目安表示(★5)、音MAD向けの初期設定と乗り換えやすい操作(★6)、iPad で歌わせる音MADが作れる(★7)、ハモりボタン(★8)。

### 姿勢(調査第2弾 1章)〔提案7〕
- **生成AIを使わない。学習もしない。素材は端末の外に出さない。** これを画面と説明ページに明記する。AI 声変換(RVC など)は内蔵しない。コミュニティは AI を「人力ではない」と区別していて、合作で禁止された例もある。
- 声のデータベースや、実在する声のプリセットを公式に配布しない(声の権利が2026年に明文化されたことを受けて)。
- 素材ごとに**出典メモ**(作品名・URL・時刻・メモ)を記録でき、投稿時の親作品登録やクレジット表記に使える。

### 引き継ぐ前提
- ピアノロールでノートを入力する。対象は PC と iPad。音質はなるべく自然に。
- TapMV と同じ構成(Vite + TypeScript、UI フレームワークなし)。TapMV のフォルダには触らない(流用するコードはコピーする)。

### やらないこと
- オーディオ録音、VST などのプラグイン、オートメーション全般、TapMV との連携、映像の扱い、AI による声の生成や変換、**素材を使わない普通のシンセ音**(論点 D。打ち込みの確認用に、正弦波のガイド音だけは用意する)

## 2. 基本フロー

```
① 素材を読み込む ─────────────▶ 自動解析(ピッチカーブ・ピッチマーク・基準ピッチ・立ち上がり)
② 素材エディタで整える
     ・鳴らす範囲を決める
     ・基準ピッチを確認する(★2)
     ・抑揚の残し具合と揺らぎを決める(★3)
     ・シンセ化マーカーを確認する(★4。自動で提案される)
   └ 編集しながら、画面の鍵盤や PC のキーですぐに試し弾きできる
③ トラックに楽器を割り当て、ピアノロールで打ち込む(ハモりボタン ★8)
④ 再生・調整 → WAV で書き出す
```

完了の目安: **素材を読み込んでから30秒以内に、鍵盤で弾ける状態になる。**

## 3. 素材の解析(★2)

素材を読み込んだときに Worker で1回だけ行い、結果を保存する。

| 解析 | 方法 | 使い道 |
|---|---|---|
| ピッチカーブ(f0)と有声らしさ | pYIN(Phase 0 で検証済み) | 表示、基準ピッチ、平坦化 |
| **ピッチマーク** | **Praat の相互相関方式(cc)**〔提案1〕(下で詳述) | PSOLA |
| 基準ピッチ | セント単位で、重み付き中央値を取る〔提案3〕(下で詳述) | ノートとの差 |
| 立ち上がり | エネルギーの変化から求める(TapMV の `onsets.ts` をコピーして使う) | 発音位置の提案 |
| 持続区間の候補 | f0 と音量が最も安定している区間 | シンセ化マーカーの提案 |

### ピッチマーク(声帯が振動する位置)〔提案1〕
Phase 0 で使ったピーク拾い方式は、周期のばらつきが大きく、重ね合わせ合成には向かない(Praat のマニュアルに明記)。そこで、次の方式に置き換える。

1. 有声区間ごとに、中央付近で振幅が最大になる点を種にする。
2. 前の点から 0.8〜1.2 周期の範囲で、波形どうしの相互相関が最大になる点を探す。これを左右へ順に繰り返す。見つけた点は放物線補間でサブサンプル精度まで詰める。
3. 相関が 0.3 未満の点は削除し、その部分は無声として扱う。
4. 最後に、マークの間隔の外れ値をメディアンで直す。
5. ステレオ素材でも、左右の平均からマークを1組だけ求め、両チャンネルに同じマークを使う(定位が揺れないように)。

### 基準ピッチ〔提案3〕
- 重みは「音量 × 有声らしさ × 安定度(f0 があまり動いていない)」にして、セント単位の中央値を取る。
- シンセ化マーカーが決まったら、**持続区間の f0 を重視して計算し直す**。音程がすべる音は、終わり側や安定した部分の高さに聞こえるため。
- 最頻値は不安定なので使わない。
- 表示は「D4 −37¢」のように、最も近い音名とセントの差で示す。「検出値に戻す」ボタンも付ける(GarageBand と同じ)。

### 解析結果の手直し
- 区間を選んで、「オクターブ上/下に直す」「無声にする/有声にする」ができる。
- 基準ピッチの線は、縦にドラッグすると半音単位で動き、Alt を押しながらだとセント単位で動く。ダブルクリックすると、最も近い半音に合わせる(Melodyne と同じ)。

## 4. 素材シンセ(★3・★4)

### 4.1 シンセ化マーカー(★4)

```
素材:  [ s  |  a ~~~~~~~~~~~~~~~~~~~ | ぁ… ]
        頭部 ▲    持続区間              ▲ 語尾
        (子音)発音位置                語尾の開始
```

| 区間 | 鳴らし方 |
|---|---|
| **頭部** | 1回だけ、伸縮せずに鳴らす(子音を守るため。サ行を削るとタ行に聞こえる、などの作法と一致)。ノートの頭より前に出して鳴らす |
| **持続区間** | ノートが続くあいだ伸ばす。伸ばし方は3種類〔提案2〕(下の表) |
| **語尾**(論点 F) | **既定はオフ**。オフのときは、ノートを離したら約20ms(変更可)でフェードする。オンのときは、語尾の区間をそのまま鳴らす。延長の上限は「なし/1拍/1小節/無制限」から選ぶ(Otomad Helper の Legato と同じ考え方) |

持続区間の伸ばし方〔提案2〕

| モード | 内容 | 用途 |
|---|---|---|
| **周期プール**(既定) | 持続区間から安定した周期を10〜40個集める。そこから近い周期をランダムに選び続け、直前の周期には戻らないようにする。周期の長さと振幅にわずかな揺らぎを加える | 自然な持続音。同じ周期を規則的に繰り返したときの「ロボット声」を防ぐ |
| ループ | クロスフェード付きでループする(クロスフェードの長さは指定できる) | 素材の「うねり」も含めて繰り返したいとき |
| ウェーブテーブル(Phase 3) | 1〜数周期をくり返す | わざとシンセっぽく、無機質にしたいとき |

- 区間の境目は解析結果から自動で提案し、波形の上でドラッグして直せる。
- 頭部から持続区間へは、頭部の最後のマークで持続区間の最初の周期に入る。グレインどうしの重なりが、そのまま自然なクロスフェードになる。
- 無声の部分は、10ms 程度のグレインを半分ずつ重ねて扱う。伸ばすときは、時間の向きを交互に反転させる(金属的な音を防ぐため)。

### 4.2 ピッチの決まり方(★3)

ボイスが鳴っている各時点の目標ピッチは、次の式で決める。

```
目標(t) = ノート + ベンド(t) + グライド(t) + 揺らぎ(t)
          + (1 − 平坦化(t)) × (f0(t) − 基準ピッチ)
```

- **平坦化**(論点 G): 0〜100%。**既定は 0%**(元の抑揚がそのまま。REAPER のピッチ変更と同じ)。
  - 楽器全体の値に加えて、**ノートごとの上書き**と、**素材の区間ごとの指定**ができる〔提案9〕。区間ごとの指定を使うと、「頭のこぶしだけ平坦にして、後半は抑揚を残す」ことができる。
  - プリセットを用意する: 「原型(0%)」「人力(30%、頭の区間だけ 100%)」「シンセ化(100%)」。
- **揺らぎ**〔提案10〕: 平坦化と対になる「揺らぎを戻す」つまみ。Phase 1 から入れる。
  - ビブラート(深さ・速さ・かかり始めの遅れ)
  - ゆっくりした揺れ(0.5Hz 未満、数セント)
  - 細かい揺れ(10Hz 以上、数セント。周期と振幅のわずかなばらつき)。**既定でオンにし、平坦化が 100% でも残す**。こうすると「平坦なのに機械っぽくない」音になる
- **ベンドとグライド**: ピアノロールにピッチベンドを書ける。グライドは、ノート間をなめらかにつなぐ。
- 平坦化が 0% で揺らぎもないときは、f0 から計算するのを省いて、一定量のシフトとして処理する。

### 4.3 ピッチの変え方とフォルマント(論点 B)
- **長さ保持(PSOLA)を既定にする**。楽器ごとに「**速度連動**」(昔ながらの、高いほど短く声も高くなる音)に切り替えられる。
- **フォルマントのずらし**〔提案4〕: 各グレインを係数 α でリサンプルしてから並べる。ずらし量は半音で指定し、目安は ±1 程度。
  - 「大きな移調で声質を少し追従させる」オプションを付ける。移調量が ±7 半音を超えたら、フォルマントをピッチ比の 0.3〜0.5 乗だけ動かす。「ミッキーマウス声」や「巨人声」を避けるため。
- 下げる方向に大きく移調すると、グレインの間に隙間ができやすい。窓の右側の裾を、最大で2周期分まで延ばして埋める。
- **Signalsmith**(Phase 3): 和音や雑音の多い素材向け。リアルタイムではなく、編集時に音の高さごとの音声を作ってキャッシュする方式にする。

### 4.4 シンセ部分
| 部分 | 内容 | フェーズ |
|---|---|---|
| アンプ | ADSR、ベロシティで音量を変える | 1 |
| 発音 | ポリ(同時発音)、ステレオ | 1 |
| 揺らぎ | ビブラート、ゆっくりした揺れ、細かい揺れ | 1 |
| ピッチ | ベンド、グライド | 2 |
| 発音モード | モノ、レガート(つながったノートでは鳴らし直さず、ピッチだけを移す) | 3 |
| フィルター | ローパス/ハイパス、レゾナンス、エンベロープでの変化量 | 3 |

### 4.5 楽器プリセット〔提案12〕
- **ベース**: 低い「n」「m」の音などをシンセ化する用途。平坦化 100%、持続区間は周期プール、リリース短め
- **ドラム**: アタックの強い素材を、ワンショットで鳴らす(伸ばさない、速度連動も選べる)
- **人力(歌)**: 平坦化 30%(頭の区間だけ 100%)、語尾オン、ビブラートは控えめ
- **シンセ化リード**: 平坦化 100%、ビブラートあり

### 4.6 劣化の目安(★5)〔提案13〕
- ピアノロールのノートに、基準ピッチからの移調量を表示する。
  - ±5 半音を超えたら「注意」、±7 半音を超えたら「警告」。
  - 色は青(下げすぎ)と朱(上げすぎ)を使い、セントの数値やハッチングも添えて、色だけに頼らないようにする〔提案6〕。
- 声域が合わないときは、「オクターブ違いの素材を楽器に追加する」ことを勧める(多重サンプル。Phase 4)。

## 5. 音声エンジン

```
[UI スレッド] 編集 ──(曲データ・パラメータ)──▶ [AudioWorklet: Engine(1つ)]
       ▲                                       ・シーケンサー(サンプル単位で正確)
       │ 解析結果                                 ・ボイスプール(事前に確保、例 32 ボイス)
[Worker: 解析]                                  ・素材シンセ(PSOLA / 速度連動)
                                                ・ミキサー・メーター
```

- **Worklet は1つにまとめ、その中にボイスを事前に確保しておく。** AudioParam は使わない(Chromium では数に比例してコストがかかるため)。パラメータは、メッセージか共有メモリで渡す。`process()` の中ではメモリを確保しない。
- シーケンサーも Worklet の中に置く。WAV の書き出しは、同じ Engine を OfflineAudioContext で実行する。
  - Safari で動かない場合に備えて、Engine を直接まとめて処理する予備の経路を用意する。
- 性能計画:
  1. まず JS で、1ボイスあたりの処理時間を測る。
  2. 目標は、**iPad で 24〜32 ボイスを CPU 50% 未満で**鳴らすこと。
  3. 足りなければ、PSOLA の中心部分だけを WASM(SIMD)に移す。
- 素材データは、SharedArrayBuffer が使えれば共有し、使えなければ転送する(必須にはしない)。
- iPad:
  - メモリは 200〜300MB 以内に収める。
  - `audioSession.type = "playback"` は、使えるかどうかを確かめてから設定する。
  - アプリを切り替えて AudioContext が "interrupted" になったら、次のタップで再開する。

## 6. データモデル

時間の単位は **tick(PPQ = 960)**。

```ts
Project { version, id, name, tempo: TempoEvent[], timeSig: TimeSigEvent[], sources: Source[], instruments: Instrument[], tracks: Track[] }

Source {
  id, name, blobId, sampleRate, channels, durationSec
  credit: { title?, url?, timecode?, memo? }      // 出典メモ〔提案7〕
  analysis?: SourceAnalysis                        // 解析のキャッシュ
}

SourceAnalysis { hopSec, f0: Float32Array, voicedProb, rms, pitchMarks: Float64Array, markVoiced: Uint8Array, onsets: number[] }

Instrument {
  id, name, sourceId, preset?: "bass" | "drum" | "jinriki" | "synth-lead"
  range: { start, end }                            // 秒
  corrections: PitchCorrection[]
  root: { midi: number, mode: "auto" | "manual" }  // 例 61.63 = D4 −37¢
  markers: {
    attack: number                                 // 頭部の終わり = 発音位置
    sustain: { start, end, mode: "pool" | "loop" | "wavetable", crossfadeSec }
    tail: { start, enabled: boolean, limit: "none" | "beat" | "bar" | "unlimited" }
  }
  releaseFadeSec: number                           // 既定 0.02
  pitch: {
    mode: "preserve-length" | "resample"           // 既定 preserve-length
    flatten: number                                // 0–1、既定 0
    flattenRegions: { start, end, amount }[]       // 素材の区間ごとの平坦化〔提案9〕
    formant: { semitones: number, followLargeShifts: boolean }
    glideSec, bendRange
  }
  wobble: {                                        // 揺らぎ〔提案10〕
    vibrato: { depthCents, rateHz, delaySec }
    driftCents: number                             // ゆっくりした揺れ
    micro: boolean                                 // 細かい揺れ(既定 true)
  }
  amp: { attack, decay, sustain, release, velocitySens }
  voice: { mode: "poly" | "mono" | "legato", maxVoices }
  filter?: { type, cutoffHz, resonance, envAmount }   // Phase 3
}

PitchCorrection { start, end, kind: "octave-up" | "octave-down" | "unvoiced" | "voiced" }

Track { id, name, color, instrumentId, gainDb, pan, mute, solo, notes: Note[], bends: BendPoint[] }

Note { id, tick, duration, pitch, velocity, pan?: number, flatten?: number }   // pan はハモりボタン用

BendPoint { tick, cents }
```

## 7. 画面と操作

### 7.1 画面構成
```
┌──────────────────────────────────────────────────┐
│ ヘッダー: プロジェクト / 元に戻す / 再生 / BPM / 拍子 / 書き出し │
├──────────┬───────────────────────────────────────┤
│ 素材と楽器 │ トラック一覧                                 │
│ の一覧     ├───────────────────────────────────────┤
│          │ 下部パネル: ピアノロール / 素材エディタ / ミキサー     │
├──────────┴───────────────────────────────────────┤
│ 画面の鍵盤(iPad では常に表示、PC では折りたためる)             │
└──────────────────────────────────────────────────┘
```

### 7.2 素材エディタ(このアプリの顔)
```
┌───────────────────────────────────────────────┐
│ 基準ピッチ: D4 −37¢ [検出値に戻す]  プリセット: [人力 ▾]     │
│ 平坦化 ━━━●━━━ 30%   揺らぎ: ビブラート ━●━  細かい揺れ ☑    │
├───────────────────────────────────────────────┤
│ D4 ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄  ← 基準ピッチ(点線)   │
│      ╱‾ ‾∿ ∿∿ ∿‾ ‾‾╲     ← 元のピッチ(橙・細い破線)        │
│      ━━━━━━━━━━━━━━     ← 整えたあと(黄・太い実線)        │
│ ▁▃▅▇█████████████▇▅▃▁   ← 波形(暗い灰色)                 │
│ [頭部][     持続区間     ][語尾]  ← 帯とラベルで表示          │
├───────────────────────────────────────────────┤
│ ADSR / 伸ばし方 / フォルマント / 語尾 / 出典メモ   [▶ C4]   │
└───────────────────────────────────────────────┘
```
- 元のピッチは**橙の細い破線**、整えたあとは**黄の太い実線**〔提案6〕。色の約束は VocalShifter に合わせつつ、色覚の違いがあっても線の形で見分けられるようにする。
- シンセ化マーカーは、ピッチの線(黄)と重ならないよう、帯の背景色とラベルで示す。iPad ではつまみを 44pt 以上にし、長押しで拡大する。
- 平坦化のスライダーを動かすと、黄色い線がその場で変わる。鍵盤を押せば、すぐに音で確かめられる。
- 区間を選んで右クリック(iPad では長押し)すると、「この区間だけ平坦化」「オクターブを直す」「無声にする」のメニューが出る(VocalShifter と同じ流れ)。

### 7.3 ピアノロール
- **PC**(FL・REAPER 互換)
  - P で描画、E で選択、右クリックで削除。Alt を押すとスナップを外す。Shift でドラッグを横方向、Ctrl で縦方向に固定する。
  - 新しいノートは、直前に触ったノートと同じ長さになる。
  - 既定のツールは、描画と選択を兼ねる「スマートツール」にする(空白をドラッグすると範囲選択、ダブルクリックでノートを追加)。
  - 選んだノートは Shift+0 / Shift+9 で ±1 半音動かせる(REAPER 互換)。Space で再生。
- **iPad**(Logic for iPad 型)
  - 画面上部に [選択] [鉛筆] のモードボタンを置く。
  - 1本指で編集、2本指でスクロール、ピンチで拡大・縮小。
  - ノートを長押しすると拡大表示とインスペクタが出る。削除はインスペクタかゴミ箱ボタンで行う(タップでの誤削除を防ぐ)。
  - Apple Pencil は常に鉛筆として扱う。ドラッグ中に画面の端に近づくと、距離に応じた速さで自動スクロールする(速さには上限を設ける)。
- **ハモりボタン**〔提案11〕(★8、Phase 2)
  - 選んだノートを複製して、5半音下(既定)/3度上/3度下/オクターブ下に置く。
  - 元のノートとハモりのノートを、左右にパンする(既定 ±70%)。
  - 3度は、曲のキーに合わせる。
- 移調量の表示(4.6)、ピッチベンドのレーン(高めにとり、点の当たり判定を大きくする)。

### 7.4 PC キーボードで鍵盤を弾く〔提案5〕
- 割り当ては Ableton と同じにする: A の段が白鍵(A = C)、W・E・T・Y・U が黒鍵、Z/X でオクターブ、C/V でベロシティ。
- キーは物理的な位置(`KeyboardEvent.code`)で判定する。JIS 配列でも同じ位置で鳴る。
- M キーかツールバーのボタンでオン・オフを切り替える。オンの間は、1キーのショートカットを止める(修飾キー付きのショートカットは使える)。テキスト入力欄にフォーカスがあるときは、鍵盤を無効にする。
- 日本語入力(IME)がオンのままだと鍵盤が鳴らない。`isComposing`、keyCode 229、`key === "Process"` のいずれかを検知したら、「半角英数に切り替えてください」と表示する。

### 7.5 画面の鍵盤
- `touch-action: none` と、指ごとのポインタキャプチャで和音を鳴らす。押した瞬間に音を出し、指を滑らせると隣の鍵へ移る(グリッサンド)。
- 最初のタップで音声を有効にし、そのタップで最初の音も鳴らす(待たされる感じをなくす)。
- 画面全体はピンチで拡大できるようにしておく(鍵盤とキャンバスだけ拡大を止める)。

### 7.6 最初に触る場面
- ログインなしで、デモ素材の入ったサンプルプロジェクトがすぐ開く。デモ素材は自作の合成音声か、権利の明確なフリー素材を使う。
- 3ステップの案内を出す: ①素材を鳴らす ②鍵盤を押す ③ピアノロールに1音置く。目標は「30秒以内に最初の音」。
- 何もないときは、「素材をドロップ/デモを開く」の2つを示す。
- 自動保存していることを画面に示す。
- REAPER・VocalShifter・FL から来た人向けに、対応するショートカットの一覧をヘルプに載せる。

## 8. 入出力・保存
- 素材: wav / mp3 / ogg / flac / m4a、動画の音声
- ノート: ピアノロール。MIDI ファイルの読み込みは Phase 2
- 書き出し:
  - WAV(ミックス)
  - **楽器の書き出し**〔提案8〕(Phase 2): シンセ化した WAV、または音域全体を収めた SFZ(サンプラー用の定義ファイル)。REAPER や OpenUtau などと併用する人が、MADDAW を前工程の道具として使えるようにする
  - トラックごとの WAV(Phase 4)
- 保存: IndexedDB に自動保存し、元に戻すにも対応する。プロジェクトファイルにも保存でき、保存先を明示して上書き事故を防ぐ。

## 9. 技術スタック
- Vite + TypeScript、UI フレームワークなし、Vitest / Playwright
- DSP は TypeScript で書く(重い部分だけ WASM に移す)
- 依存ライブラリは MIT / BSD 系だけにする(Signalsmith は MIT。Rubber Band、Praat、PyTSMod などの GPL / AGPL のコードは使わず、論文や文書に書かれた手法だけを参考にする)
- 公開: Cloudflare(静的配信。`_headers` で COOP/COEP を設定)

## 11. 決定事項(論点 B〜G)

| 論点 | 決定 |
|---|---|
| A. 基準キーの決め方 | セント単位で自動判定し、手で直せる(v1.1 で決定) |
| B. ピッチの変え方 | 長さ保持(PSOLA)が既定。楽器ごとに速度連動へ切り替えられる |
| C. フェーズの振り分け | 10章のとおり |
| D. 素材を使わないシンセ音 | 入れない。打ち込み確認用の正弦波ガイド音だけ用意する。代わりにベース・ドラムの楽器プリセットとハモりボタンに力を入れる |
| E. Phase 0 のコード | 検証ページは削除する。pYIN と基準ピッチ判定は Worklet と Worker 向けに作り直す。ピッチマークは cc 方式で書き直す。テストと合成音声の生成器は引き継ぐ |
| F. 語尾 | Phase 1 に入れるが、既定はオフ(ノートを離すと約20msでフェード)。オンにすると、延長の上限を選べる |
| G. 平坦化の既定値 | 0%。プリセットとして「人力 30%」「シンセ化 100%」を用意する。細かい揺れは既定でオンにし、100% でも残す |
